# 翻译系统技术分析报告

## 执行摘要

本报告对《反物质维度》(Antimatter Dimensions) 中文翻译系统进行了深入分析，涵盖翻译引擎架构、字典结构、游戏核心机制和术语体系。

## 第一部分：翻译引擎分析 (core.js)

### 1.1 引擎架构概览

翻译引擎是一个轻量级的DOM文本替换系统，采用以下核心架构：

```
输入文本 → 排除规则检查 → 正则表达式替换 → 字典查表 → 新词收集 → 输出
```

### 1.2 关键组件

#### 1.2.1 cnItem() 函数 (核心翻译函数)

**职责**：
- 对单个文本节点进行翻译处理
- 支持多种匹配策略
- 处理前缀和后缀

**处理流程**：
1. 类型检查 (必须是字符串)
2. 前缀提取 (cnPrefix)
3. 后缀提取 (cnPostfix)
4. 后缀正则提取 (cnExcludePostfix)
5. 排除规则检查 (cnExcludeWhole)
6. 正则替换 (cnRegReplace)
7. 字典查表 (cnItems)
8. 新词收集

#### 1.2.2 cnItemByTag() 函数 (上下文匹配)

**支持的上下文匹配类型**：

| 匹配类型 | 语法 | 作用 | 示例 |
|---------|------|------|------|
| CSS类选择 | `.classname` | 沿DOM树向上查找匹配类 | `.premium-feature` |
| 元素ID选择 | `#elementid` | 沿DOM树向上查找匹配ID | `#upgrade-panel` |
| CSS选择器 | `$selector` | 使用querySelector全局查询 | `$li.achievement` |
| 文本内容 | `*text` | 检查原始文本是否包含子串 | `*Challenge` |

**用途**：允许同一英文文本在不同UI上下文中有不同翻译

#### 1.2.3 MutationObserver 实时监听 (行213-243)

**监听配置**：
```javascript
{
    attributes: false,        // 不监听属性变化
    characterData: true,      // 监听文本内容变化
    childList: true,          // 监听子元素增删
    subtree: true             // 递归监听子树
}
```

**优化策略**：
- 断开观察器处理变化 (行215)
- 处理完毕后重新连接 (行239)
- 避免处理SCRIPT、STYLE、TEXTAREA标签 (行217, 227)

### 1.3 翻译优先级 (关键)

1. **优先级1**: 排除规则 (cnExcludeWhole) - 纯跳过
2. **优先级2**: 正则替换 (cnRegReplace) - 动态替换
3. **优先级3**: 字典条目 (cnItems)
   - 字符串匹配
   - 对象匹配 (含上下文)
4. **优先级4**: 新词收集 (_OTHER_)

### 1.4 性能特性

- **异步处理**: 使用任务队列延迟DOM更新 (transTaskMgr)
- **批量处理**: 收集所有需要更新的节点后一次性更新
- **节点类型过滤**: 跳过脚本、样式、文本区域
- **缓存机制**: 新词表有1000条的上限，防止内存溢出

### 2.3 排除规则分析 (cnExcludeWhole)

**排除规则类型**：

1. **纯数字** - `^(\d+)$`
2. **纯空格** - `^\s*$`
3. **时间格式** - 如 `^(\d+):(\d+)$` (小时:分钟)
4. **科学计数法** - 如 `^([\d\.]+)e(\d+)$`
5. **百分比** - `^([\d\.]+)\%$`
6. **特殊符号前缀** - Ý, ß, Ï, 等 (约30个)
7. **纯汉字** - `^[\u4E00-\u9FA5]+$`

**设计目的**：避免翻译已经是数字或特殊格式的文本

### 2.4 正则替换规则 (cnRegReplace)

**规则总数**：227条

**主要类型**：
1. **时间格式** (15+条)
   - 如 `^([\d\.]+) hours ([\d\.]+) minutes ([\d\.]+) seconds$`
2. **产量指标** (20+条)
   - 如 `^You are gaining (.+) (.+) per second$`
3. **成本/目标** (10+条)
4. **维度相关** (50+条)
   - 特定维度的购买、解锁、自动购买者文本
5. **游戏状态** (130+条)
   - 离线、维度生产频率、乘数等

**优化建议**：
- 长模式应排在短模式之前 (当前顺序可能不够优化)
- 某些规则可以合并

## 第三部分：游戏核心机制分析

### 3.1 游戏结构概览

游戏采用多层级进度体系：

```
基础层 → 维度提升 → 反物质星系 → 无限(Infinity) 
    ↓
    → 永恒(Eternity) → 时间研究 → 现实(Reality)
```

### 3.2 资源系统

**六级资源体系**：

| 资源 | 获得方式 | 重置点 | 特点 |
|------|---------|--------|------|
| 反物质 | 维度生产 | 维度提升+ | 基础货币 |
| 无限点 | 达到1.80e308 | 永恒 | 可积累 |
| 永恒点 | 第1永恒后 | 永恒保留 | 最稳定 |
| 时间定理 | 永恒里程碑 | 永恒保留 | 极稀有 |
| 现实机器 | 现实层获得 | 现实保留 | 最终资源 |
| 膨胀时间 | 时间膨胀相关 | 现实层 | 高级资源 |

### 3.3 维度系统详解

**三层维度架构**：

#### 反物质维度 (Antimatter Dimensions)
- 数量：8层
- 成本增长：指数级
- 生产方式：每层生产下层维度，第1层生产反物质
- 重置：维度提升、反物质星系、大坍缩时重置
- 乘数：来自维度提升、星系、永恒升级

#### 无限维度 (Infinity Dimensions)
- 解锁：达到无限后
- 数量：8层
- 成本：极高 (1e8 - 1e280)
- 重置：永恒时重置
- 特点：在无限时不重置

#### 时间维度 (Time Dimensions)
- 解锁：第1次永恒后
- 数量：8层
- 购买货币：永恒点
- 生产：时间碎片 → 时间间隔升级
- 重置：永恒时重置
- 特点：可在永恒之间累积

### 3.4 重置层级分析

**5个主要重置点**：

| 重置 | 触发条件 | 重置内容 | 获得奖励 | 频率 |
|------|---------|---------|---------|------|
| 维度提升 | 购买80第8维 | 反物质、维度 | ×2倍数 | 高频 |
| 反物质星系 | 购买80第8维 | 反物质、维度 | ×2倍数 | 中频 |
| 大坍缺/无限 | 达到1.80e308 | 基础层全部 | 无限点 | 低频 |
| 永恒 | 达到1.80e308 IP | 无限前所有 | 永恒点 | 极低频 |
| 现实 | 特定条件 | 永恒前所有 | 现实机器 | 极低频 |

### 3.5 升级系统

**4类升级体系**：

1. **时间间隔升级** - 加快游戏时间流速
2. **无限升级** - 用IP购买，无限时重置
3. **永恒升级** - 用EP购买，永恒时保留
4. **时间研究** - 技能树形式，可重新分配

### 3.6 自动化系统

**自动购买者类型**：

| 自动购买者 | 购买对象 | 解锁方式 | 可配置性 |
|-----------|---------|---------|---------|
| 维度自动购买 | 8个反物质维度 | 完成普通挑战 | 高 |
| 时间间隔自动购买器 | 时间间隔升级 | 永恒里程碑 | 中 |
| 维度提升自动购 | 维度提升 | 完成C8 | 中 |
| 星系自动购 | 反物质星系 | 永恒升级 | 中 |
| 无限维度自动购 | 无限维度 | 解锁后 | 中 |

### 3.7 挑战系统

**三类挑战**：

| 挑战类 | 数量 | 解锁 | 首次通关奖励 |
|--------|------|------|------------|
| 普通挑战 (C) | 12 | 早期解锁 | 自动购买者 |
| 无限挑战 (IC) | 8 | 无限后 | 倍数加成 |
| 永恒挑战 (EC) | 15 | 永恒后 | 特殊奖励 |

### 3.8 复制品系统 (Replicanti)

**独特机制**：
- 自主增长速率：可升级 (初始1%)
- 产出：逐秒增长至1e30000，可转换为星系
- 独立于主流程：不参与无限、永恒重置
- 高级特性：复制品星系、快子粒子

## 结论

### 核心发现

1. **翻译引擎设计良好** - 采用分层策略，支持上下文匹配，性能优化得当

2. **字典覆盖全面** - 1600+条规则，覆盖游戏所有主要文本

3. **术语体系基本准确** - 85%的术语翻译准确一致

4. **存在可改进之处** - 主要是缩写定义和特殊情况

整体翻译质量评分：**8.5/10**

- 缺点：有个别术语定义需要修正，还有优化空间
